# Transformer architecture upgrade (smc-trainer)

Date: 2026-09-11. Repo: `~/csand/umapsp` (worktree of `specialty-umap`), file
`smc-trainer/transformer.lisp` (+ `trainer-tests.lisp`, `README.md`).

## What changed

`smc-trainer/transformer.lisp` went from a toy single-head, single-block
Transformer to a real multi-head, multi-layer pre-norm encoder, still 100%
dependency-free Common Lisp (native arrays, `aref`, no BLAS/LAPACK/Quicklisp/
ASDF), reusing the existing scalar-level reverse-mode autodiff engine
(`ad-node` graph) and Adam optimizer unchanged.

- **Tokenization** (unchanged): each scalar feature becomes a `d-model`-dim
  token via a per-feature identity embedding + linear scalar projection. This
  identity embedding doubles as positional encoding since each feature always
  occupies the same slot.
- **Multi-head attention**: `d-model` splits into `num-heads` heads of size
  `d-model/num-heads`, each with its own Q/K/V projections; per-head outputs
  are concatenated and mixed through a shared output projection.
- **Multi-layer stack**: `num-layers` encoder blocks, each pre-norm:
  `x + sublayer(norm(x))`, with a learnable-gain RMSNorm (the old version had
  no learnable gain and used post-norm). Final RMSNorm before mean-pooling to
  the 2D output.
- **Defaults**: 2 heads x 2 layers (chosen with the user), `d-model=8`,
  `d-ff=12`, feed-forward activation kept as `tanh` (not switched to GELU, by
  user's choice, to minimize risk since I could not execute SBCL myself while
  writing this).
- Configurable via `initialize-parametric-model`'s `:num-heads`/`:num-layers`
  keywords (defaults `*trainer-num-heads*`/`*trainer-num-layers*`). `d-model`
  must be evenly divisible by `num-heads` (checked, errors otherwise).

## Backward compatibility (important design decision)

Old `:parametric-feature-transformer :version 1` saved models (single head,
single block, gain-less post-norm) are **not** reinterpreted through the new
math -- that would silently change predictions for anything already trained.
Instead the original computation is preserved byte-for-byte under a
`:legacy-single-head` model "kind"; `parametric-model` is effectively a
tagged union (`kind` = `:legacy-single-head` or `:multi-head-stack`).
`transformer-forward`, `parametric-model-parameter-groups`,
`parametric-model-form`, and `form-parametric-model` all dispatch on `kind`/
`:version`. Freshly initialized models are always `:multi-head-stack`, saved
as `:version 2`.

Practical effect: `smc-trainer/specialty-awrs-model.sexp`,
`candidate-nine-transformer.sexp`, `candidate-fixed-atlas-model.sexp` (all
`:version 1`) keep loading and predicting exactly as before, with **no
retraining required**. Confirmed on real data: `tests/candidate-map-tests.lisp`
(which exercises `candidate-fixed-atlas-model.sexp` against all 143
specialties) passes 6/6, 690 assertions, unchanged.

Public API preserved exactly (no changes needed in `train.lisp`,
`predict.lisp`, `shards.lisp`, `specialty-specific/train-candidate-map.lisp`,
or the nine-feature pipeline scripts): `initialize-parametric-model`,
`transformer-forward`/`parametric-forward`, `parametric-predict`,
`parametric-coordinate-loss`, `parametric-model-parameters`,
`make-adam-state`, `adam-update`, `train-one-observation`,
`parametric-model-form`, `form-parametric-model`, `save-parametric-model`,
`load-parametric-model`.

## Test results (run by the user on their Mac; I could not execute SBCL myself)

`sbcl --script vendor/test-cases/run-tests.lisp smc-trainer/trainer-tests.lisp`
-- 5/6 pass. New/updated tests: multi-head/multi-layer shape checks,
num-heads-must-divide-d-model guard, a hand-built `:version 1` fixture
exercising the legacy path end-to-end (round-trips byte-identical), and the
one-observation overfit+round-trip test (now self-contained, no longer reads
an external corpus fixture) -- confirms Adam actually drives loss down
4+ orders of magnitude through the new 2-head/2-layer pre-norm stack, and
serialization round-trips predictions exactly.

One pre-existing, unrelated failure: `FITTED-ARTIFACT-PREDICTS-FROM-RAW-FEATURES`
needs `smc-trainer/weights/pilot-coordinate-baseline.sexp`, which does not
exist in this checkout. Likewise `smc-trainer/corpus/pilot-shards/manifest.sexp`
was missing (this is why the overfit test was made self-contained). Neither
fixture is generated by any script currently documented in TOUR.md/README --
looks like a gap from before this session, not something I introduced. Not
fixed as part of this work.

`sbcl --script vendor/test-cases/run-tests.lisp tests/candidate-map-tests.lisp`
-- 6/6 pass, 690 assertions. This is the strongest confirmation: it runs the
*real* `candidate-fixed-atlas-model.sexp` (legacy `:version 1`, trained on all
143 specialties) through the new dispatch code and checks predictions are
finite and beat the mean-coordinate baseline.
